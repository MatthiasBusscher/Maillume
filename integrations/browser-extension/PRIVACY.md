# Browser Extension Privacy

The extension reads only text the user explicitly selects, or the visible currently open message in Gmail or Outlook when no text is selected, after the user invokes the Maillume toolbar action. Chrome's temporary `activeTab` grant is used immediately to inspect accessible frames. The extension has no persistent Gmail or Outlook host permission. It sends the reviewed subject, sender, and message text to the deployment shown in the panel only after **Analyze message** is pressed.

Extension-local storage contains the chosen deployment URL, the dedicated revocable browser credential, its hard and inactivity expiries, and a random browser installation identifier so the connection survives browser restarts and extension updates. Access is restricted to trusted extension contexts. A managed browser credential is never placed in the manual API-key field or otherwise revealed in the panel after connection. The installation identifier is not an account credential; the server receives and stores only its SHA-256 hash. Manual API-key configuration remains available under **Advanced manual setup** for self-hosting, development, recovery, and older deployments. A manual key can be retained locally or only for the current browser session.

**Connect this browser** uses a ten-minute device-authorization request. The extension briefly keeps a random device code, pairing ID, deployment, approval URL, and expiry in session storage so it can resume polling after the side panel is reopened. The approval page uses the user's existing Maillume account session; account credentials and session tokens never pass to the extension. The server stores only hashes of the device code, browser installation identifier, and issued credential, plus bounded connection metadata. The plaintext credential is returned to the approved extension once. Reconnecting from the same Chrome profile revokes and replaces its previous credential.

**Remove connection** clears both credential-storage locations and any pending connection request. The non-secret installation identifier stays local so a later reconnect can replace any still-active server credential for that same browser profile. Captured content is held briefly in service-worker memory for a one-time, tab-specific panel handoff and expires after at most one minute. A session-only recovery descriptor contains only the capture ID, state, and expiry, allowing the panel to request a fresh tab read after service-worker suspension without storing message text or results. Message text and results otherwise remain only in the open panel's memory. No message content or result is written to extension storage. The extension does not use persistent content scripts, background mailbox scanning, cookies, browsing history, advertising identifiers, or analytics.

The selected Maillume deployment controls server-side processing. The official service privacy notice is at `https://maillume.io/privacy`.
